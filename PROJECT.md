# TaskbarFold

Утилита для Windows 10/11: мини-папки в панели задач. Клик по иконке группы
открывает компактное всплывающее окно с ярлыками приложений — как папки на iPhone.

**Статус:** реализовано — версия 0.1.0, все этапы M0–M6
**Платформа:** Windows 10 (1809+) и Windows 11
**Лицензия:** MIT

---

## 1. Проблема

Панель задач вмещает 10–15 иконок, дальше начинается свалка. Windows не умеет
группировать закреплённые ярлыки — нет ни папок, ни вложенности.

Существующее решение, open-source `tjackenpacken/taskbar-groups`, заброшено
с января 2021 года: 259 открытых issues, 14 висящих PR, WinForms на
.NET Framework 4.7.2, написано до выхода Windows 11.

## 2. Целевой сценарий

Пользователь держит на панели задач 4–6 групп вместо 30 иконок:
«Работа», «Дизайн», «Игры», «Утилиты». Один клик — всплывашка — второй клик
или цифра на клавиатуре — приложение запущено. Полный путь до запуска
занимает меньше секунды.

## 3. Отличия от taskbar-groups

| Проблема в taskbar-groups | Решение в TaskbarFold |
|---|---|
| Холодный старт процесса на каждый клик | Резидент в трее, окно предсоздано и скрыто |
| Нет DPI-awareness, размеры в пикселях | PerMonitorV2 в манифесте, все размеры в DIP |
| Индекс монитора считается неверно | `Screen.FromPoint` для конкретного экрана |
| Идентичность группы = её имя | Неизменяемый GUID + отдельное отображаемое имя |
| Конфиг рядом с .exe, требует UAC | Конфиг в `%APPDATA%\TaskbarFold` |
| Блокирующий HTTP-запрос в конструкторе UI | Проверка обновлений асинхронно, с кэшем |
| Закрепление в 4 ручных шага | Кнопка «Закрепить» + Проводник с выделенным .lnk |
| Порядок иконок только через окно настроек | Drag & drop прямо во всплывашке |
| Нет поиска | Type-to-search по группе |
| Битый путь = крестик навсегда | Резервные признаки + автоперепривязка |

## 4. Технический стек

- **.NET 8**, C# 12
- **WPF** — всплывашка и окно настроек (нужна нормальная работа с DPI и анимациями)
- **CommunityToolkit.Mvvm** — MVVM без лишнего
- **H.NotifyIcon.Wpf** — иконка в трее
- **System.Text.Json** — конфиг
- **xUnit** — тесты для доменного слоя
- Публикация: `win-x64`, self-contained, single-file

## 5. Архитектура

Один исполняемый файл в двух режимах, различаются по аргументу командной строки:

```
TaskbarFold.exe                    → окно настроек + резидент в трее
TaskbarFold.exe --group <GUID>     → сигнал резиденту показать всплывашку
```

Второй режим не создаёт UI: он находит уже запущенный резидент через именованный
pipe, передаёт GUID и завершается. Резидент показывает предсозданное окно.
Если резидента нет — поднимает его и повторяет запрос.

### Проекты в решении

```
TaskbarFold.sln
├── src/
│   ├── TaskbarFold.Core/        доменная логика, без ссылок на UI
│   │   ├── Models/              Group, Shortcut, AppSettings
│   │   ├── Services/            GroupRepository, ShortcutResolver
│   │   └── Interop/             ShellLink, IconExtractor, TaskbarInfo, AppxResolver
│   ├── TaskbarFold.App/         WPF: окна, ViewModel, трей
│   └── TaskbarFold.Tests/       xUnit по Core
└── docs/
```

Правило: `Core` не знает про WPF. Всё, что связано с окнами и рендерингом,
живёт только в `App`. Interop-обёртки над WinAPI возвращают чистые модели.

## 6. Модель данных

Конфиг: `%APPDATA%\TaskbarFold\groups.json` — один файл на все группы.
Кэш иконок: `%APPDATA%\TaskbarFold\cache\<group-guid>\<shortcut-guid>.png`.

```jsonc
{
  "version": 1,
  "groups": [
    {
      "id": "b3f1...",              // GUID, неизменяемый, основа AppUserModelID
      "name": "Работа",             // можно переименовать без потери закрепления
      "iconPath": "...",
      "columns": 5,
      "background": "#1F1F1F",
      "opacity": 0.92,
      "shortcuts": [
        {
          "id": "a7c2...",
          "displayName": "Photoshop",
          "target": "C:\\Program Files\\Adobe\\...\\Photoshop.exe",
          "arguments": "",
          "workingDirectory": "C:\\Program Files\\Adobe\\...",
          "appUserModelId": null,   // заполнено для UWP/Store-приложений
          "fallbackFileName": "Photoshop.exe",  // для автоперепривязки
          "runAsAdmin": false
        }
      ]
    }
  ]
}
```

`AppUserModelID` формируется как `TaskbarFold.Group.{id}`. Это критично: без
уникального AUMID Windows склеит все группы в одну кнопку на панели задач.
Привязка идёт к GUID, а не к имени — переименование группы не ломает закрепление.

## 7. Дорожная карта

| Этап | Содержание | Оценка |
|---|---|---|
| M0 | Каркас, доменные модели, репозиторий конфига, тесты | 3–4 дня |
| M1 | Interop: иконки, .lnk с AUMID, позиция панели задач | 4–5 дней |
| M2 | Всплывашка: позиционирование, запуск, закрытие по фокусу | 4–5 дней |
| M3 | Окно настроек: CRUD групп, drag & drop, выбор иконки | 5–7 дней |
| M4 | Резидент в трее, named pipe, автозапуск | 2–3 дня |
| M5 | Поиск, клавиатура, контекстное меню, автоперепривязка | 4–5 дней |
| M6 | Установщик, автообновление, публикация | 3–4 дня |

Итого до публичной беты: примерно 5–6 недель работы одного разработчика.

## 8. Задачи

Все пункты M0–M6 реализованы. Отклонения от исходного плана отмечены курсивом —
везде, где реализация оказалась лучше или надёжнее задуманного.

### M0 — каркас

- [x] Solution, три проекта, `Directory.Build.props` с общими настройками
- [x] `app.manifest`: `PerMonitorV2`, `asInvoker`, поддержка Windows 10/11
- [x] Модели `Group`, `Shortcut`, `AppSettings`
- [x] `IGroupRepository`: чтение и запись `groups.json`, атомарная запись
      через временный файл + `File.Replace`
- [x] Миграция схемы по полю `version`
- [x] Тесты: сериализация, круговой цикл save/load, битый JSON

*`Load` возвращает `ConfigLoadResult` со статусом, а не просто документ: битый файл
уезжает в `groups.corrupt-<дата>.json`, а конфиг от более новой версии не трогается
вообще — иначе первое же сохранение затёрло бы данные, которые новая версия понимает.*

### M1 — interop

- [x] `IconExtractor`: иконка из .exe и .lnk, с выбором максимального размера
- [x] `AppxResolver`: получение AUMID и логотипа для Store-приложений
      из `shell:AppsFolder`; разбор `AppxManifest.xml` — вспомогательный путь
- [x] `ShellLink`: создание .lnk через `IShellLink` + `IPropertyStore`
      с записью `System.AppUserModel.ID`
- [x] `TaskbarInfo`: сторона, размер, режим автоскрытия; корректная работа
      при нескольких мониторах
- [x] Генерация многоразмерного .ico (16/24/32/48/64/128/256)
- [x] Кэш иконок с инвалидацией по времени изменения и размеру исходного файла

*Основной путь извлечения иконки — `IShellItemImageFactory`, а не `SHGetFileInfo`:
он одинаково работает для файлов и для упакованных приложений и отдаёт самый крупный
имеющийся ресурс. `SHGetFileInfo` / `ExtractIconEx` оставлены запасным вариантом.*

*Сторона панели задач определяется по разнице между прямоугольником монитора и его
рабочей областью, а `ABM_GETTASKBARPOS` используется только как запасной путь:
этот вызов описывает лишь основную панель — из-за чего taskbar-groups и промахивался
мимо нужного экрана.*

*Кадры .ico меньше 128 px пишутся как DIB, а не PNG: `System.Drawing.Icon` не умеет
декодировать PNG-кадры, а он всё ещё стоит на пути части системных потребителей.*

### M2 — всплывающее окно

- [x] Borderless-окно, `Topmost`, `ShowInTaskbar = false`, акриловый фон
- [x] Позиционирование по монитору под курсором, прижатие к нужной стороне
      панели задач, отступ 8 DIP, коррекция при выходе за границы экрана
- [x] Обработка автоскрытой панели задач
- [x] Закрытие: потеря фокуса, Esc, запуск приложения
- [x] Анимация появления: 120 мс, fade + сдвиг на 8 DIP
- [x] Сетка иконок: колонки из конфига, размер ячейки в DIP
- [x] Запуск: `Process.Start` с `UseShellExecute = true`;
      для UWP — через `shell:AppsFolder\{AUMID}`
- [x] Понятная ошибка вместо `MessageBox` с текстом исключения

*Окно позиционируется через `SetWindowPos` в физических пикселях, а не через
`Window.Left/Top`: при per-monitor DPI логические координаты WPF относятся к текущему
DPI-контексту окна, и при переходе между экранами с разным масштабом оно промахивается.*

*Процесс `--group` передаёт резиденту право поднять окно (`AllowSetForegroundWindow`).
Без этого Windows не даёт фоновому процессу выйти на передний план, и всплывашка
создаётся и тут же скрывается по потере фокуса.*

### M3 — окно настроек

- [x] Список групп, создание, удаление, дублирование
- [x] Редактор группы: имя, иконка, число колонок, цвет, прозрачность
- [x] Добавление ярлыков: диалог выбора, drag & drop из Проводника,

- [x] Переупорядочивание ярлыков перетаскиванием
- [x] Поля: отображаемое имя, аргументы, рабочая папка, запуск от администратора
- [x] Кнопка «Закрепить на панели задач»: генерирует .lnk, открывает Проводник
      командой `explorer.exe /select,"путь"` и показывает подсказку
- [x] Живой предпросмотр всплывашки

### M4 — резидент

- [x] Иконка в трее, меню: настройки, автозапуск, папка ярлыков, выход
- [x] Named pipe `TaskbarFold.{SID}` для передачи GUID от режима `--group`
- [x] Единственный экземпляр через именованный мьютекс
- [x] Предсозданные скрытые окна групп, прогрев кэша иконок при старте
- [x] Автозапуск через `HKCU\...\Run` (не через планировщик — не требует прав)

на той же машине не могла открывать чужие всплывашки.*

- [x] Type-to-search: набор текста фильтрует иконки, Enter запускает первую

- [x] Глобальные горячие клавиши на открытие конкретной группы
- [x] Контекстное меню на иконке: запустить от администратора, открыть

## 9. Технические риски

**Программное закрепление на панели задач невозможно.** Windows 10/11 намеренно
закрыли API. Обходные пути через реестр и `LayoutModification.xml` работают
нестабильно и ломаются обновлениями. Принимаем как данность: закрепление
остаётся ручным, задача — свести его к одному клику и наглядной подсказке.

**Store-приложения не имеют пути к .exe.** Только AUMID. Требует отдельной
ветки и в запуске, и в извлечении иконки.

**Пересборка .lnk сбрасывает закрепление.** Поэтому .lnk генерируется один раз
при создании группы и дальше только правится на месте, без пересоздания файла.

**Акриловый фон.** `DwmSetWindowAttribute` с `SystemBackdrop` доступен только
на Windows 11 build 22621+. Для Windows 10 — сплошной цвет с прозрачностью.

## 10. Вне рамок MVP

Вложенные группы, синхронизация конфига между машинами, плагины,
поддержка macOS и Linux, замена панели задач своим доком, виджеты
и живые превью окон.
